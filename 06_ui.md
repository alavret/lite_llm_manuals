Инструкция: включаем встроенный Admin UI (веб-интерфейс) в существующую установку LiteLLM (Ubuntu, без Docker, systemd — по [01_setup_litellm.md](01_setup_litellm.md), nginx — по [05_nginx.md](05_nginx.md)).

Симптом, который лечим: при входе в UI по адресу `https://litellm.domain.com/ui` (или `http://IP_UBUNTU:4000/ui`) браузер показывает:

```text
Authentication Error
Not connected to DB!
```

Причина: Admin UI требует два условия (см. https://docs.litellm.ai/docs/proxy/ui):

1. задан `master_key` — у вас уже есть (`LITELLM_MASTER_KEY`);
2. к прокси подключена база данных PostgreSQL — её пока нет.

UI хранит в БД пользователей, виртуальные ключи, бюджеты и статистику расходов, поэтому без БД он не работает. Ниже — как поставить PostgreSQL рядом с прокси и подключить его.

Схема после выполнения инструкции:

```text
Браузер
    →  https://litellm.domain.com/ui   (nginx :443, TLS)
    →  http://127.0.0.1:4000/ui        (LiteLLM Proxy + Admin UI)
    →  127.0.0.1:5432                  (PostgreSQL, только localhost)

GUI-клиенты (Chatbox и т.п.)
    →  https://litellm.domain.com/v1   (как раньше, ничего не меняется)
```

## 1. Что понадобится

- установленная по [01_setup_litellm.md](01_setup_litellm.md) установка: venv `/opt/litellm/venv`, конфиги `/etc/litellm/config.yaml` и `/etc/litellm/litellm.env`, systemd-служба `litellm`;
- ~100 МБ диска под PostgreSQL;
- права `sudo`.

Проверка текущего состояния (до изменений):

```bash
curl -sS http://127.0.0.1:4000/health -H "Authorization: Bearer $LITELLM_MASTER_KEY"
```

Прокси отвечает — идём дальше.

## 2. Установка PostgreSQL

Ставим из штатного репозитория Ubuntu:

```bash
sudo apt update
sudo apt install -y postgresql
sudo systemctl enable --now postgresql
```

Проверка:

```bash
sudo systemctl status postgresql --no-pager
```

По умолчанию PostgreSQL слушает только `127.0.0.1:5432` — наружу БД не торчит, это нас устраивает.

## 3. База и пользователь для LiteLLM

Сгенерируйте пароль БД:

```bash
openssl rand -hex 24
```

Создайте пользователя и базу (пароль подставьте свой):

```bash
sudo -u postgres psql -c "CREATE USER litellm WITH PASSWORD 'ВАШ_ПАРОЛЬ_БД';"
sudo -u postgres psql -c "CREATE DATABASE litellm OWNER litellm;"
```

Проверка подключения:

```bash
psql "postgresql://litellm:ВАШ_ПАРОЛЬ_БД@127.0.0.1:5432/litellm" -c '\conninfo'
```

Должно отработать без ошибок. Таблицы создавать не нужно — пустой базы достаточно: схему (таблицы Prisma) вы создадите в разделе 6. Важно: при pip-установке LiteLLM **не создаёт таблицы сам** даже при старте с БД — без шага `prisma db push` из раздела 6 UI будет падать с `TableNotFoundError`.

## 4. Переменные окружения

Откройте `/etc/litellm/litellm.env`:

```bash
sudo nano /etc/litellm/litellm.env
```

Добавьте строки (существующие не трогаем):

```bash
# Подключение к PostgreSQL для Admin UI / виртуальных ключей / бюджетов
DATABASE_URL=postgresql://litellm:ВАШ_ПАРОЛЬ_БД@127.0.0.1:5432/litellm

# Соль для шифрования ключей провайдеров, добавляемых через UI.
# Сгенерируйте один раз: openssl rand -base64 32
# ВАЖНО: после первого использования никогда не меняйте —
# ключи, зашифрованные старым значением, станет невозможно расшифровать.
LITELLM_SALT_KEY=СТРОКА_ИЗ_openssl_rand_base64_32

# Логин и пароль для входа в Admin UI (https://docs.litellm.ai/docs/proxy/ui).
# Без них вход по умолчанию: admin / LITELLM_MASTER_KEY.
# Имя можно оставить admin, пароль задайте свой — отдельный от мастер-ключа:
UI_USERNAME=admin
UI_PASSWORD=ОТДЕЛЬНЫЙ_ПАРОЛЬ_ДЛЯ_UI
```

Генерации:

```bash
# соль для LITELLM_SALT_KEY
openssl rand -base64 32

# пароль для UI_PASSWORD
openssl rand -base64 18
```

Пароль для UI не совпадает с `LITELLM_MASTER_KEY` намеренно: мастер-ключ ходит в API-маршруты, а этот — только в веб-форму входа.

Права не меняем — файл уже `root:litellm 640`.

## 5. Правка config.yaml

Откройте `/etc/litellm/config.yaml`:

```bash
sudo nano /etc/litellm/config.yaml
```

В `general_settings` добавьте `database_url` (в остальном конфиг не меняется — ваши модели из `model_list` продолжат работать и появятся в UI):

```yaml
model_list:
  - model_name: corp-llm
    litellm_params:
      model: openai/gemma-4-31b-it
      api_base: https://gpt.mwsapis.ru/projects/alavret/openai/v1/
      api_key: os.environ/CUSTOM_LLM_TOKEN
      timeout: 120
      stream_timeout: 120

general_settings:
  master_key: os.environ/LITELLM_MASTER_KEY
  database_url: os.environ/DATABASE_URL

litellm_settings:
  drop_params: true
  request_timeout: 120
```

| Поле | Зачем |
|---|---|
| `database_url` | включает Admin UI, виртуальные ключи, бюджеты, spend tracking |
| `LITELLM_SALT_KEY` (env) | шифрует ключи провайдеров, которые добавляете через UI |

Опционально — если хотите управлять моделями (добавлять/убирать) прямо из UI без правки `config.yaml`, добавьте в `litellm_settings`:

```yaml
litellm_settings:
  drop_params: true
  request_timeout: 120
  store_model_in_db: true   # модели из UI сохраняются в БД, конфиг не правится
```

## 6. Установка Prisma-клиента и создание таблиц (обязательно для pip-установки)

LiteLLM работает с БД через Prisma. В Docker-образе Prisma-клиент, бинарники и схема БД уже готовы, а при установке через `pip` — нет: без этого раздела служба упадёт на старте с ошибками:

```text
ModuleNotFoundError: No module named 'prisma'
Exception: Unable to find Prisma binaries. Please run 'prisma generate' first.
```

Шаг 1 — установить пакет `prisma` в тот же venv:

```bash
sudo -u litellm /opt/litellm/venv/bin/pip install 'prisma==0.15.0'
```

Версия критична. В litellm ≤ 1.99.x есть баг (issue #39114, исправление — PR #39116): с prisma-client-py ≥ 0.13 каждое обращение к БД падает с `AttributeError: 'Prisma' object has no attribute '_Prisma__engine'`, и служба бесконечно перезапускает подключение. Официально litellm тестирует prisma `0.11.0`, но её установка и `generate` нередко виснут на скачивании engine-бинарников. Рабочая связка — свежий prisma + патч одной строки (шаг 3). В litellm новее 1.99.x баг исправлен — патч не нужен.

Шаг 2 — сгенерировать Prisma-клиент по схеме LiteLLM (нужен доступ в интернет — Prisma скачает engine-бинарники; путь к site-packages может отличаться, проверьте: `ls /opt/litellm/venv/lib/python3.12/site-packages/litellm/proxy/schema.prisma`):

```bash
sudo -u litellm bash -c 'export PATH=/opt/litellm/venv/bin:$PATH && cd /opt/litellm/venv/lib/python3.12/site-packages/litellm/proxy && prisma generate'
```

`export PATH=...` обязателен: `sudo` сбрасывает `PATH` до системного, и без этого Node-CLI Prisma не найдёт генератор `prisma-client-py` (он лежит в `/opt/litellm/venv/bin`) и упадёт с ошибкой:

```text
Error: Generator "prisma-client-py" failed:
/bin/sh: 1: prisma-client-py: not found
```

Успешный результат заканчивается строкой вида:

```text
Generated Prisma Client Python (v0.15.0) to ./../../prisma in XXXms
```

Проверка, что модуль появился:

```bash
sudo -u litellm /opt/litellm/venv/bin/python -c 'from prisma import Prisma; print("prisma ok")'
```

Шаг 3 — пропатчить несовместимость litellm ≤ 1.99.x с prisma ≥ 0.13 (см. шаг 1). Файл `litellm/proxy/db/prisma_client.py`, функция `_write_engine`, записывает движок в приватный атрибут, которого в новых версиях prisma больше нет, — заменяем на публичный сеттер:

```bash
sudo sed -i 's/prisma_client\._Prisma__engine = engine/prisma_client._engine = engine/' \
  /opt/litellm/venv/lib/python3.12/site-packages/litellm/proxy/db/prisma_client.py
```

Патч затирается при каждом обновлении litellm — см. «Важно» в конце раздела.

Шаг 4 — создать таблицы в БД. pip-установка НЕ применяет схему сама: litellm при старте, если бинарник `prisma` не входит в `PATH` systemd-службы (его там нет), даже не проверяет схему, а при проверке лишь пишет нужный SQL в журнал, не выполняя его. Применяем схему вручную:

```bash
sudo -u litellm bash -c 'set -a; source /etc/litellm/litellm.env; set +a; export PATH=/opt/litellm/venv/bin:$PATH; cd /opt/litellm/venv/lib/python3.12/site-packages/litellm/proxy && prisma db push --accept-data-loss --skip-generate'
```

Успешный результат:

```text
Your database is now in sync with your Prisma schema. Done in XXXs
```

Без этого шага UI (и всё, что хранится в БД) падает с `TableNotFoundError: LiteLLM_Config` либо «Not connected to DB!». `--accept-data-loss` безопасен: на пустой БД терять нечего; на уже существующей — не выполняйте его без бэкапа (раздел 10).

Важно: после каждого обновления `litellm` (`pip install -U 'litellm[proxy]'`) повторяйте шаги 2 и 4 (`prisma generate` + `prisma db push`) — схема БД в новой версии могла измениться; а если ваша версия litellm ≤ 1.99.x, обновление затрёт и патч из шага 3 — примените его заново.

Если меняете версию prisma, сначала удалите пакет начисто вместе со сгенерированными файлами (иначе `generate` падает со странностями вида `module 'prisma._types' has no attribute 'SortMode'` — в site-packages остаются файлы от старой версии):

```bash
sudo -u litellm /opt/litellm/venv/bin/pip uninstall -y prisma
sudo rm -rf /opt/litellm/venv/lib/python3.12/site-packages/prisma
```

и только затем ставьте новую версию (шаг 1) и повторяйте шаги 2–4.

## 7. Перезапуск и первичная инициализация

```bash
sudo systemctl restart litellm
sudo journalctl -u litellm -f
```

Таблицы уже созданы в разделе 6, поэтому LiteLLM просто подключается к БД. Успешный старт в журнале выглядит так:

```text
Application startup complete.
Uvicorn running on http://127.0.0.1:4000 (Press CTRL+C to quit)
```

Строк контейнерной установки вида «Prisma schema loaded / Applying migrations» здесь НЕ будет — при pip-установке схему применяет `prisma db push` из раздела 6, а не сам litellm.

Не пугайтесь и такого шума в журнале (это нормально):

- `Unable to connect to DB. DATABASE_URL found in environment, but pri...` — появляется в самом начале старта, до инициализации подключения; бывает и при полностью рабочей БД;
- `401 ... No api key passed in` — чей-то запрос без ключа (сканеры, health-проверки снаружи);
- `Error: Decryption failed. Ciphertext failed verification` + `Set permanent salt key` — кто-то передал в `Authorization` не-virtual-key (например, JWT или чужой токен), litellm попытался расшифровать его как ключ БД и не смог.

Старт занимает 10–60 секунд. Дождитесь строки про успешный старт прокси, затем проверьте health:

```bash
sudo bash -c '
  set -a
  source /etc/litellm/litellm.env
  set +a
  curl -sS http://127.0.0.1:4000/health -H "Authorization: Bearer ${LITELLM_MASTER_KEY}"
'
```

И что API-маршрут не сломался:

```bash
sudo bash -c '
  set -a
  source /etc/litellm/litellm.env
  set +a
  curl -sS http://127.0.0.1:4000/v1/models -H "Authorization: Bearer ${LITELLM_MASTER_KEY}"
'
```

Должен вернуться список с `corp-llm`.

Замечание по systemd: у службы `ProtectSystem=strict`, `ReadOnlyPaths=/etc/litellm /opt/litellm` и `ReadWritePaths=/var/log/litellm`. Prisma-движки лежат внутри venv и запускаются из read-only каталога — это нормально, запись им не нужна. Если в вашей конфигурации служба всё же упала с ошибкой про запись в `/opt/litellm/...`, добавьте в unit `ReadWritePaths=/opt/litellm/venv/lib` и выполните `daemon-reload` + `restart`.

## 8. Вход в UI

Откройте в браузере:

```text
https://litellm.domain.com/ui      # если настроен nginx (05_nginx.md)
http://IP_UBUNTU:4000/ui           # если заходите напрямую (порт 4000 открыт)
```

Данные для входа по умолчанию (если в разделе 4 не заданы `UI_USERNAME`/`UI_PASSWORD`):

| Поле | Значение |
|---|---|
| Username | `admin` |
| Password | значение `LITELLM_MASTER_KEY` (целиком, с префиксом `sk-litellm-`) |

nginx из [05_nginx.md](05_nginx.md) уже проксирует все пути, включая `/ui`, — отдельная настройка не нужна.

Как это работает: без сессии `/ui` перенаправляет на страницу логина; форма отправляет `POST /v2/login`, при успехе в БД создаётся/обновляется пользователь `admin` и выдаётся JWT-сессия (если первый вход — в журнале появятся строки про вставку в User Table, это нормально).

Если вы задали в разделе 4 `UI_USERNAME`/`UI_PASSWORD` (рекомендуется, чтобы не логиниться мастер-ключом) — используйте их. Смена позже: правьте эти строки в `/etc/litellm/litellm.env` и перезапустите `sudo systemctl restart litellm`.

После входа доступны:

- **Models** — список моделей из `config.yaml` (и добавление новых через UI при `store_model_in_db: true`);
- **Virtual Keys** — выпуск отдельных ключей для пользователей/приложений с бюджетами и лимитами вместо раздачи мастер-ключа;
- **Usage / Spend** — статистика запросов и расходов;
- **Logs** — лог запросов с задержками и токенами;
- **Playground** — тестовые запросы к моделям прямо из браузера.

## 9. Что меняется для клиентов

Ничего. GUI-клиенты продолжают ходить в `https://litellm.domain.com/v1` с `LITELLM_MASTER_KEY` и моделью `corp-llm`.

Рекомендация: после появления UI заведите в **Virtual Keys** отдельный ключ для GUI-клиента и перейдите на него вместо мастер-ключа — так у ключа будут свои лимиты/бюджет, а мастер-ключ останется только для администрирования.

## 11. Типовые проблемы

| Симптом | Причина / решение |
|---|---|
| `Authentication Error, Not connected to DB!` | `DATABASE_URL` не задан или БД недоступна; проверьте разделы 3–5 и `journalctl -u litellm -e` |
| В журнале повторяется `TableNotFoundError: LiteLLM_Config` (и т.п.) | таблицы БД не созданы — не выполнен шаг 4 раздела 6 (`prisma db push`) |
| `AttributeError: 'Prisma' object has no attribute '_Prisma__engine'` | litellm ≤ 1.99.x + prisma ≥ 0.13 (issue #39114): примените патч из шага 3 раздела 6 или поставьте prisma 0.11.0 |
| `ModuleNotFoundError: No module named 'prisma'` / `Unable to find Prisma binaries` | не выполнен раздел 6: `pip install prisma` + `prisma generate` в каталоге `litellm/proxy` |
| `prisma generate`: `prisma-client-py: not found` | venv не в `PATH` при запуске через `sudo`; используйте команду с `export PATH=/opt/litellm/venv/bin:$PATH` из раздела 6 |
| `prisma generate` висит минутами / падает с ошибкой скачивания | нет доступа в интернет с сервера (Prisma качает engine-бинарники); убейте зависший процесс и повторите, при повторении проверьте прокси/firewall |
| После смены версии prisma: `module 'prisma._types' has no attribute 'SortMode'` и подобное | в site-packages остались сгенерированные файлы старой версии; удалите пакет начисто (конец раздела 6) и повторите шаги 1–4 |
| `Error: Decryption failed. Ciphertext failed verification` + `Set permanent salt key` | в `Authorization` передан не виртуальный ключ (например, JWT или случайный токен) — сам по себе не ошибка; если повторяется от ваших клиентов, они шлют не тот токен. `LITELLM_SALT_KEY` при этом не меняйте (раздел 4) |
| Логин `admin` + мастер-ключ не принимается | вводите ключ целиком с префиксом `sk-`; если заданы `UI_USERNAME`/`UI_PASSWORD` — используются они |
| Служба падает на старте после добавления БД | `journalctl -u litellm -e`; чаще всего опечатка в `DATABASE_URL` или БД не создана |
| `Error: database connection refused` | PostgreSQL не запущен (`systemctl status postgresql`) или слушает не `127.0.0.1:5432` |
| В UI не видны модели из `config.yaml` | это нормально для моделей, объявленных в конфиге; включите `store_model_in_db: true`, чтобы управлять моделями из UI |
| UI открылся, но «Test» у модели падает | проверьте `CUSTOM_LLM_TOKEN` и доступность `api_base` с сервера (см. раздел 12 в [01_setup_litellm.md](01_setup_litellm.md)) |
| Первый старт долго висит | смотрите `journalctl -u litellm -f`; сам litellm миграции не выполняет — таблицы создаёт `prisma db push` (раздел 6, шаг 4) |
| UI нужно выключить | `DISABLE_ADMIN_UI=True` в `/etc/litellm/litellm.env` + `systemctl restart litellm` |

## Короткий чеклист

1. `apt install postgresql`, создать пользователя `litellm` и базу `litellm`.
2. В `/etc/litellm/litellm.env` добавить `DATABASE_URL`, один раз сгенерированный `LITELLM_SALT_KEY` и `UI_USERNAME`/`UI_PASSWORD` для входа в UI.
3. В `/etc/litellm/config.yaml` в `general_settings` добавить `database_url: os.environ/DATABASE_URL` (опционально `store_model_in_db: true`).
4. `pip install 'prisma==0.15.0'` в venv + `prisma generate` в каталоге `litellm/proxy` + патч `_write_engine` (для litellm ≤ 1.99.x) — раздел 6.
5. `prisma db push --accept-data-loss --skip-generate` с подгруженным `DATABASE_URL` — создать таблицы (шаги 4–5 повторять после каждого обновления litellm).
6. `systemctl restart litellm`, дождаться `Application startup complete` в `journalctl`.
7. Зайти на `https://litellm.domain.com/ui`: логин/пароль из `UI_USERNAME`/`UI_PASSWORD` (по умолчанию `admin` / `LITELLM_MASTER_KEY`).
8. Выпустить виртуальный ключ для GUI-клиентов и перевести их с мастер-ключа на него.
